# 客户2：思睦达（SMO）- 临床试验中心选择智能系统需求分析

## 一、业务背景

### 1.1 客户概况
- **客户名称**: 思睦达（SMO - Site Management Organization）
- **业务领域**: 临床试验现场管理
- **核心业务**: 为制药企业提供临床试验中心选择、启动、执行、监查等全流程服务

### 1.2 行业挑战
- **数据规模**: 自2013年以来积累31,336个临床试验、1,400家中心、23,000名研究者的数据
- **核心问题**: 11%的中心入组0例受试者，37%的中心表现不达预期
- **根本矛盾**: "纸面资质"与"实际表现"的严重不匹配
- **决策困境**: 依赖专家经验，缺乏数据支撑，选择周期长达2-3周

### 1.3 业务价值
- 提高临床试验成功率和入组速度
- 降低中心选择错误带来的时间和成本损失
- 将中心选择决策从"经验驱动"转变为"数据驱动"

## 二、核心业务场景

### 2.1 临床试验全生命周期

```
项目获取 → 可行性评估 → 机构/研究者选择 → 启动准备 →
  → 试验执行 → 数据管理 → 结题归档
```

**本需求聚焦**: 机构/研究者选择阶段（最关键的决策环节）

### 2.2 中心选择端到端流程：五阶段决策模型

```
Search(搜索) → Identify(识别) → Compare(对比) → Confirm(确认) → Simulate(模拟)
```

---

### 阶段1: Search - 智能搜索与发现

#### 业务目标
从海量中心/研究者数据中快速找到候选对象

#### 典型场景

**场景1.1: 语义化搜索**
- **用户输入**: "擅长肺癌三期临床试验的研究者"
- **系统处理**:
  1. 理解语义: "肺癌" → ICD编码、适应症本体
  2. "三期临床" → 试验分期、样本量要求
  3. "擅长" → 历史成功率、入组速度等综合指标
- **输出**: 排序后的研究者列表，附带匹配度评分

**场景1.2: 相似案例检索**
- **用户输入**: "找与项目X相似的历史项目及其使用的中心"
- **系统处理**:
  1. 提取项目X的特征向量（适应症、分期、入排标准、受试者画像）
  2. 向量相似度计算，检索相似项目
  3. 关联查询这些项目使用的中心及其表现
- **输出**: 相似项目列表 + 中心表现数据

**场景1.3: 多维度筛选**
- **用户输入**: 地理位置（华东）+ 病床数(>500) + GCP资质 + 近一年无重大违规
- **系统处理**: 组合条件过滤，支持模糊匹配和范围查询
- **输出**: 符合条件的中心列表

**场景1.4: 聚合分析**
- **用户输入**: "各省肺癌试验中心的数量分布"
- **系统处理**: 按地理维度聚合统计
- **输出**: 可视化地图热力图 + 统计表

#### 核心痛点
| 当前问题 | 具体表现 | 解决方案 |
|---------|---------|---------|
| 关键词搜索不准 | 搜"肺癌"搜不到"非小细胞肺癌" | 基于医学本体的语义搜索 |
| 无法搜索隐性能力 | 想找"入组快的中心"无从搜索 | 构建能力标签体系 |
| 历史经验难复用 | 不知道类似项目用了哪些中心 | 案例向量化+相似度检索 |

### 阶段2: Identify - 关键指标识别与风险评估

#### 业务目标
深入了解候选中心的真实能力和潜在风险

#### 典型场景

**场景2.1: 能力全景画像**
- **输入**: 选定某个中心
- **输出**: 多维度能力仪表盘
  - **基础资质**: GCP证书、伦理委员会、床位数、科室设置
  - **历史业绩**: 参与试验数量、完成率、入组速度、方案偏离率
  - **专业能力**: 擅长适应症、擅长试验分期、受试者画像匹配度
  - **协作能力**: CRC配置、沟通响应速度、文档质量
  - **风险指标**: 违规记录、投诉记录、人员流动率

**场景2.2: 关键指标自动识别**
- **输入**: 项目特征（如"儿童罕见病三期试验"）
- **系统推理**:
  1. 识别该类项目的关键成功因素（如"儿童科室完善度"、"罕见病经验"）
  2. 从历史数据中学习：哪些指标与成功率强相关
  3. 自动高亮这些关键指标
- **输出**: 动态调整的指标优先级

**场景2.3: 置信度评估**
- **挑战**: 某些中心数据样本量小，指标可信度低
- **解决方案**:
  - 计算统计置信区间（如"历史入组速度: 2.5人/月，置信度: 70%"）
  - 样本量不足时，借用相似中心的群体数据作为先验
- **输出**: 每个指标附带置信度标识

**场景2.4: 风险自动识别**
- **输入**: 候选中心列表
- **系统分析**:
  1. 检查硬性风险（如GCP即将过期、有重大违规记录）
  2. 检查软性风险（如近期研究者离职、入组趋势下滑）
  3. 基于规则和模型评估风险等级
- **输出**: 风险清单 + 风险等级（高/中/低）+ 建议措施

#### 核心痛点
| 当前问题 | 具体表现 | 解决方案 |
|---------|---------|---------|
| 信息过载 | 每个中心几十个指标，看不过来 | 智能识别关键指标 |
| 数据可信度不明 | 不知道数据是来自1个项目还是100个项目 | 置信度评估 |
| 风险识别靠经验 | 容易遗漏隐蔽风险 | 自动化风险扫描 |

### 阶段3: Compare - 多中心对比分析

#### 业务目标
在多个候选中心之间进行系统化对比，支持决策

#### 典型场景

**场景3.1: 多维度对比矩阵**
- **输入**: 选择3-5个候选中心
- **输出**: 对比表格

| 维度 | 中心A | 中心B | 中心C | 最优 |
|-----|-------|-------|-------|------|
| 入组速度 | 3.2人/月 ⭐️⭐️⭐️ | 2.1人/月 ⭐️⭐️ | 4.5人/月 ⭐️⭐️⭐️⭐️ | C |
| 完成率 | 92% ⭐️⭐️⭐️⭐️ | 78% ⭐️⭐️ | 88% ⭐️⭐️⭐️ | A |
| 方案偏离率 | 3% | 8% | 5% | A |
| 地理位置 | 上海 | 北京 | 广州 | - |
| 成本(估算) | 150万 | 130万 | 160万 | B |

**场景3.2: 优劣势分析**
- **输入**: 对比矩阵
- **系统生成**: 自然语言总结
  - "中心C在入组速度上有明显优势，但成本较高"
  - "中心A的试验完成率最高，适合对质量要求严格的项目"
  - "中心B性价比最高，但方案偏离率需关注"

**场景3.3: 场景化对比**
- **输入**: 选择对比场景（如"快速入组场景" vs "质量优先场景"）
- **系统处理**: 根据不同场景调整指标权重
  - 快速入组: 入组速度权重↑, 成本权重↑
  - 质量优先: 完成率权重↑, 方案偏离率权重↑
- **输出**: 不同场景下的推荐排序

**场景3.4: 雷达图可视化**
- **输入**: 候选中心
- **输出**: 多维能力雷达图，直观展示各中心的综合能力轮廓

#### 核心痛点
| 当前问题 | 具体表现 | 解决方案 |
|---------|---------|---------|
| Excel手工对比 | 耗时且容易遗漏维度 | 自动化对比矩阵 |
| 难以权衡取舍 | 各有优劣，不知如何选择 | 场景化推荐 |
| 缺乏可视化 | 纯数字难以直观理解 | 雷达图、热力图 |

---

### 阶段4: Confirm - 决策确认与行动计划

#### 业务目标
完成最终决策，自动生成后续行动计划

#### 典型场景

**场景4.1: 智能推荐排序**
- **输入**: 项目需求 + 候选中心池
- **系统推理**:
  1. 基于项目特征匹配历史成功模式
  2. 综合多维度指标计算综合得分
  3. 考虑约束条件（如预算上限、地理分布要求）
- **输出**: 推荐列表（Top 5） + 推荐理由

**场景4.2: 决策依据留存**
- **用户操作**: 选择最终中心
- **系统记录**:
  - 决策时间
  - 候选中心列表及其评分
  - 用户选择的理由（手工输入或模板选择）
  - 关键指标快照（用于后续复盘）
- **价值**: 支持后续效果评估和经验沉淀

**场景4.3: 自动生成行动清单**
- **输入**: 确认的中心
- **系统生成**: 后续待办事项
  - [ ] 联系中心负责人（联系人: 张三, 电话: xxx）
  - [ ] 提交伦理审查材料（截止日期: 2026-02-15）
  - [ ] 组织启动会（建议时间: 2026-02-20）
  - [ ] 准备培训材料（负责人: 李四）
  - [ ] 签署合同（法务对接: 王五）

**场景4.4: 风险预案制定**
- **输入**: 选定中心的已识别风险
- **系统建议**: 针对每个风险的应对措施
  - 风险: "该中心近期人员流动率较高"
  - 预案: "与中心签订人员稳定承诺" + "准备备选中心"

#### 核心痛点
| 当前问题 | 具体表现 | 解决方案 |
|---------|---------|---------|
| 决策依据未留存 | 后续复盘时不记得为什么选了这个中心 | 决策记录系统 |
| 后续流程手工驱动 | 选定后不知道下一步做什么 | 自动生成行动清单 |
| 风险应对被动 | 问题出现才想到应对 | 主动生成风险预案 |

---

### 阶段5: Simulate - 场景模拟与预测

#### 业务目标
通过模拟和预测，提前评估决策效果，优化中心组合

#### 典型场景

**场景5.1: 入组进度预测**
- **输入**: 选定的中心组合 + 项目目标（如"12个月内入组300例"）
- **模型**: 基于历史数据训练的入组速度预测模型
  - 特征: 中心历史入组速度、适应症匹配度、季节因素、地理分布
  - 输出: 每月预测入组曲线 + 置信区间
- **输出**:
  - 预测结果: "预计12个月入组280例（置信度80%），存在20例缺口"
  - 建议: "建议增加1-2个备选中心"

**场景5.2: What-If场景模拟**
- **输入**:
  - 当前方案: 中心A+B+C
  - 模拟方案: 中心A+B+D（用D替换C）
- **系统计算**:
  - 预测入组速度变化
  - 成本变化
  - 风险变化
- **输出**: 两方案对比表 + 建议

**场景5.3: 风险情景模拟**
- **输入**: 选定的中心组合
- **系统模拟**:
  - 情景1: 如果某个中心表现不及预期（入组速度下降50%）
  - 情景2: 如果某个中心中途退出
  - 情景3: 如果入排标准收紧导致受试者池缩小
- **输出**: 各情景下的项目完成时间和成本预测 + 应对建议

**场景5.4: 中心组合优化**
- **输入**: 项目约束条件（预算、时间、质量要求、地理分布）
- **系统优化**:
  - 基于约束规划算法，求解最优中心组合
  - 目标函数: 最小化成本 + 最小化风险 + 最大化入组速度
- **输出**: 推荐的最优中心组合方案（可能推荐多个帕累托最优解）

#### 核心痛点
| 当前问题 | 具体表现 | 解决方案 |
|---------|---------|---------|
| 无法预判风险 | 项目执行过程中才发现入组进度落后 | 入组进度预测 |
| 方案调整成本高 | 中心选定后难以调整 | What-If模拟支持决策前优化 |
| 缺乏应急预案 | 中心退出时措施不足 | 风险情景模拟 |

## 三、核心痛点深度分析

### 3.1 数据痛点

| 痛点 | 具体表现 | 数据来源 | 解决方案 |
|------|---------|---------|---------|
| 数据分散 | 中心资质在监管平台、项目数据在CRM、受试者数据在EDC | 多个系统 | 统一数据湖 |
| 数据不完整 | 新中心缺少历史数据，老中心数据未持续更新 | 各系统 | 补全策略+持续采集 |
| 数据质量差 | 地址不规范、联系方式过期、指标计算口径不一致 | 人工录入 | 数据清洗+质量规则 |
| 隐性知识未沉淀 | 专家知道"这个中心虽然数据好看但协作困难" | 专家经验 | 知识标签化+主观评价采集 |

### 3.2 决策痛点

| 痛点 | 具体表现 | 业务影响 | 解决方案 |
|------|---------|---------|---------|
| 过度依赖专家 | 只有少数专家掌握中心选择经验 | 人员变动影响业务、无法规模化 | 知识结构化+AI辅助 |
| 决策不透明 | 不知道专家为什么推荐这个中心 | 难以复制、难以审计 | 决策过程可视化 |
| 历史经验难复用 | 不记得类似项目用了哪些中心、效果如何 | 重复踩坑 | 案例库+相似度检索 |
| 缺乏量化支撑 | 主观判断为主，缺少数据支持 | 决策风险高 | 指标体系+预测模型 |

### 3.3 效率痛点

| 痛点 | 具体表现 | 时间成本 | 解决方案 |
|------|---------|---------|---------|
| 信息收集慢 | 需要从多个系统、多个文件中查找中心信息 | 2-3天 | 统一检索入口 |
| 人工对比耗时 | Excel手工整理、逐个对比 | 1-2天 | 自动化对比工具 |
| 沟通成本高 | 需要多轮会议讨论才能达成一致 | 3-5次会议 | 数据驱动的共识 |
| 方案迭代慢 | 调整方案需要重新分析 | 0.5-1天/次 | 实时模拟能力 |

### 3.4 风险痛点

| 痛点 | 具体表现 | 业务后果 | 解决方案 |
|------|---------|---------|---------|
| 风险识别不全 | 依赖人工检查，容易遗漏 | 项目执行中暴露问题 | 自动风险扫描 |
| 缺乏预案 | 中心表现不达预期时措施不足 | 项目延期、成本增加 | 风险情景模拟 |
| 后验评估缺失 | 不知道历史选择决策的效果如何 | 无法持续优化 | 效果追踪与复盘 |

## 四、涉及系统与数据

### 4.1 数据源系统

| 系统 | 数据类型 | 数据量级 | 更新频率 | 关键实体 |
|------|---------|---------|---------|---------|
| 药物临床试验登记平台 | 试验基本信息、中心列表 | 3万+试验 | 实时 | 试验、中心、研究者 |
| CRM系统 | 中心联系信息、沟通记录 | 1400+中心 | 日度 | 中心、联系人、沟通记录 |
| EDC系统 | 受试者入组、访视数据 | 百万级记录 | 实时 | 受试者、访视、不良事件 |
| CTMS系统 | 项目进度、里程碑 | 万级项目 | 日度 | 项目、任务、文档 |
| 监查报告系统 | 中心监查记录、发现问题 | 十万级记录 | 周度 | 监查访问、发现、CAPA |
| 监管平台 | GCP证书、违规记录 | 千级中心 | 季度 | 中心资质、合规记录 |
| 医院信息系统 | 门诊量、病床数、科室设置 | 千级医院 | 年度 | 医院、科室、设备 |

### 4.2 核心数据实体

**中心实体**:
- 基础属性: 中心名称、地址、等级、床位数、科室设置
- 资质属性: GCP证书、伦理委员会等级、PI资质
- 历史业绩: 参与试验列表、入组速度、完成率、方案偏离率
- 能力标签: 擅长适应症、擅长试验分期、受试者画像
- 风险标签: 违规记录、投诉记录、人员流动情况

**研究者实体**:
- 基础属性: 姓名、职称、科室、联系方式
- 专业背景: 教育经历、执业年限、专业领域
- 历史业绩: 主持试验数量、入组速度、论文发表
- 协作能力: 沟通响应速度、文档质量评分

**试验实体**:
- 基础属性: 试验编号、适应症、分期、申办方
- 设计属性: 入排标准、访视计划、样本量
- 执行属性: 使用的中心列表、实际入组情况、完成情况
- 受试者画像: 年龄分布、性别分布、地理分布

### 4.3 知识与规则

**领域知识**:
- **医学本体**: 疾病分类（ICD-10）、适应症层级、药物分类（ATC）
- **试验知识**: 试验分期定义、GCP规范、伦理审查流程
- **评价标准**: 中心能力评价维度、风险评级规则

**业务规则**:
- **匹配规则**: 中心-项目匹配度计算公式
- **风险规则**: 风险识别条件（如"6个月内2次违规→高风险"）
- **推荐规则**: 综合评分权重、排序算法

**统计模型**:
- **入组预测模型**: 基于历史数据的时间序列预测
- **相似度模型**: 试验-试验相似度、中心-项目匹配度
- **风险评估模型**: 基于多因素的风险评分模型

### 5.2 智能检索层

#### 功能3: 语义化搜索引擎
- **功能描述**: 支持自然语言输入，理解用户意图，返回精准结果
- **输入**: 自然语言查询（如"擅长儿童肿瘤的三甲医院"）
- **处理过程**:
  1. NLP解析: 提取关键实体和意图
  2. 本体映射: "儿童肿瘤" → 疾病编码 + 年龄约束
  3. 图谱检索: 在知识图谱中查询匹配路径
  4. 排序: 按相关度评分排序
- **输出**: 排序后的结果列表 + 匹配度评分 + 高亮匹配原因

#### 功能4: 相似案例检索
- **功能描述**: 基于向量相似度，检索与当前项目相似的历史案例
- **向量化特征**:
  - 试验特征: 适应症、分期、设计类型、样本量
  - 中心特征: 能力标签、地理位置、历史业绩
- **相似度算法**: 余弦相似度、欧式距离、基于图嵌入的相似度
- **输出**: Top-K相似案例 + 相似度评分 + 关键相似点说明

#### 功能5: 多维筛选与聚合分析
- **功能描述**: 支持复杂条件组合筛选和多维度统计聚合
- **筛选条件**: 支持精确匹配、范围查询、模糊匹配、组合逻辑
- **聚合维度**: 按地理、按适应症、按时间等
- **输出**: 筛选结果集 + 聚合统计图表

### 5.3 智能分析层

#### 功能6: 能力画像生成
- **功能描述**: 自动生成中心/研究者的多维能力画像
- **输入**: 中心ID或研究者ID
- **分析逻辑**:
  1. 从历史数据提取业绩指标
  2. 从知识图谱推理能力标签
  3. 从规则库计算风险评分
- **输出**: 结构化画像数据 + 可视化仪表盘

#### 功能7: 风险自动识别
- **功能描述**: 基于规则和模型，自动扫描候选中心的潜在风险
- **风险类型**:
  - 合规风险: GCP证书过期、历史违规记录
  - 能力风险: 历史业绩不佳、样本量不足
  - 协作风险: 人员流动、沟通响应慢

#### 功能9: 场景化推荐
- **功能描述**: 根据不同业务场景（快速入组、质量优先、成本优先）调整推荐策略
- **场景定义**: 每个场景对应不同的指标权重配置
- **推荐算法**: 加权综合评分 + 约束满足
- **输出**: Top-N推荐列表 + 推荐理由

### 5.4 预测与模拟层

#### 功能10: 入组进度预测
- **功能描述**: 基于历史数据和机器学习模型，预测未来入组进度

### 6.2 关键技术方案

#### 6.2.1 临床试验知识图谱构建（OntoLogic）

**实体建模**:
```
中心实体:
  - 属性: 中心名称, 地址, 等级, 床位数, GCP证书有效期
  - 关系:
    - 隶属于(医院)
    - 拥有(科室)
    - 参与(试验)
    - 雇佣(研究者)
    - 被监管于(监管机构)

试验实体:
  - 属性: 试验编号, 适应症, 分期, 样本量, 入排标准
  - 关系:
    - 针对(适应症)
    - 使用(药物)
    - 在...进行(中心)
    - 由...负责(研究者)
    - 属于(申办方)

研究者实体:
  - 属性: 姓名, 职称, 科室, 执业年限
  - 关系:
    - 就职于(中心)
    - 擅长(专业领域)
    - 主持(试验)
```

**知识推理规则**:
```
规则1: 中心能力推理
  IF 中心A参与适应症X的试验次数 >= 5次
  AND 平均入组速度 > 行业中位数
  THEN 推理: 中心A擅长适应症X

规则2: 风险推理
  IF 研究者离职时间 < 6个月
  AND 该研究者是PI
  THEN 推理: 中心存在人员风险(高)

规则3: 匹配度推理
  IF 项目适应症 = 中心擅长适应症
  AND 项目分期 = 中心历史主要分期
  AND 地理位置满足要求
  THEN 推理: 匹配度 = 高
```

#### 6.2.2 语义搜索实现（OntoLogic + NexusLink）

**搜索流程**:
1. **NLP解析**: 使用LLM提取用户查询中的实体和意图
   - 输入: "擅长肺癌三期临床试验的研究者"
   - 解析结果:
     - 实体类型: 研究者
     - 适应症: 肺癌（ICD-10: C34）
     - 试验分期: III期
     - 隐含条件: 历史业绩良好

2. **本体扩展**: 基于医学本体扩展查询范围
   - "肺癌" → [非小细胞肺癌, 小细胞肺癌, 肺腺癌...]
   - "三期" → [III期, 3期, Phase III]

3. **图谱查询**: 在知识图谱中执行Cypher查询
```cypher
MATCH (r:研究者)-[:主持]->(t:试验)-[:针对]->(d:疾病)
WHERE d.ICD_code STARTS WITH 'C34'  // 肺癌编码
  AND t.分期 = 'III'
WITH r, COUNT(t) AS 试验数量, AVG(t.入组速度) AS 平均入组速度
WHERE 试验数量 >= 3
  AND 平均入组速度 > 2.0  // 行业基准
RETURN r, 试验数量, 平均入组速度
ORDER BY 平均入组速度 DESC
LIMIT 20
```

4. **相关性评分**: 综合多个维度计算相关性
   - 适应症匹配度: 0.4
   - 历史业绩: 0.3
   - 试验数量: 0.2
   - 时间衰减(近期项目权重高): 0.1

5. **结果展示**: 排序后返回，高亮匹配原因

#### 6.2.3 入组预测模型（Axiom）

**特征工程**:
- **中心特征**:
  - 历史入组速度（6个月、12个月均值）
  - 当前负载（正在进行的项目数）
  - 适应症匹配度
  - 受试者库规模（门诊量）
- **项目特征**:
  - 适应症罕见度
  - 入排标准严格程度
  - 竞争试验数量
- **时间特征**:
  - 季节因素（春节、暑期影响入组）
  - 趋势因素（项目前期慢、中期快、后期慢）

**模型选择**:
- **时间序列模型**: ARIMA、Prophet（适合有明显季节性）
- **机器学习模型**: XGBoost、LightGBM（适合多特征）
- **深度学习模型**: LSTM、Transformer（适合复杂时序依赖）

**模型评估**:
- MAPE（平均绝对百分比误差）< 15%
- 置信区间覆盖率 > 80%

**预测输出**:
```json
{
  "预测结果": {
    "第1月": {"预测入组": 25, "置信区间": [20, 30]},
    "第2月": {"预测入组": 32, "置信区间": [27, 37]},
    ...
    "第12月": {"预测入组": 18, "置信区间": [15, 22]}
  },
  "总计": {"预测总入组": 280, "目标入组": 300},
  "风险评估": "存在20例缺口，建议增加备选中心",
```
